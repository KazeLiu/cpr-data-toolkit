Codex Proxy RS 的连接与用量导入、统计维护和请求身份维护插件，项目标识为 `cpr-data-toolkit`，开发目录为 `D:\code\cpr-data-toolkit`。

项目包含 Rust 后端和 Vue 管理页，本工作树交付版本为 **1.9**（包内 `1.9.0`），要求 CPR **3.33.0 或更新的兼容版本**，使用 RPC v7、公开 SDK **0.1.0**、upstream_adapter v5 和 middleware v6，不兼容旧 RPC。SDK 与打包 CLI 固定到 [CPR v3.33.0 的提交 `8c8618aa`](https://github.com/zyycn/codex-proxy-rs/commit/8c8618aa0f841638262262e3338c115bc075f125)，安装入口见 `docs/installation.md`

本次仅交付 Linux ARM64 本地安装包，尚未创建 GitHub Release。已发布版本见 [Releases](https://github.com/KazeLiu/cpr-data-toolkit/releases)。旧 RPC 宿主应先升级，不能只改清单版本号

## 功能标签页

- **上游额度**：默认进入此页并聚合全部已配置上游，卡片显示额度与原币种余额，模型详情弹窗支持搜索和点击复制
- **API 导入**：解析 CCS 完整手动 SQL 导出，提取 Claude、Codex 和 Gemini 的名称、地址与 Key，选择后通过宿主账号合同接入 OpenAI Responses 兼容上游，不按来源协议拦截。表格支持多选、跨页全选、复制 API，以及主动查看或复制隐藏的 Key。相同地址与 Key 只接入一次，名称不同在弹窗中选择；更新已有账号使用精确凭据版本
- **用量导入**：按应用、模型和来源时区的请求时间筛选完整 CCS 来源，预览 Token、费用与原生请求疑似重复项。确认后替换所选时段内该来源的全部旧贡献，再写入筛选结果；保留源内代理／会话去重、稳定记录键、时段外贡献、CPR 原生请求和其他来源
- **手动调整**：填写 Token 总量和请求次数的正负增减量，读取今天／近 7 天／近 30 天的真实原值并预览，确认后写入首次提交时刻。结果未确认时保留原操作 ID，重新打开页面可继续核对
- **模型定价**：读取、同步和批量维护 CPR 全局价目；社区价目支持关键词与模型 ID 过滤，缓存价格缺失或留空按零处理，输入与输出价格必填。「价格同步」按选定时间和 Provider 补全缺失费用或覆盖该范围原生请求的 Token 估算费用
- **模型UA定制**：忽略大小写，按顺序使用第一条命中的启用规则覆盖 `User-Agent`；可选配套 `originator`、`version`，未填写的头不变更，未命中不改写。预览和安全验证用绿／红色块显示结果；请求改写日志展示时间、模型、命中规则及替换前后 UA
- **模型上游优先级**：按完整模型名称查询同一 Provider 下的上游，拖拽或使用上移／下移设置首选与备用顺序；最近请求对照插件选择与最终上游，查看首选／备用是否匹配
- **Cline 接入**：在同一个 Tab 选择已有 Cline 账号启用 Responses → Chat Completions 转换、配置 DeepSeek 钉选并查看实际提供方；账号凭据、调度和代理仍由 CPR 管理

## 通过 CPR 调用 Cline 并钉住 DeepSeek

调用链为 `下游 Responses → CPR 选号 → 插件转换与钉选 → Cline Chat Completions → 插件返回 Responses`。下游只配置 CPR 地址和 CPR Client Key，不接触 Cline Key，也不需要 CPA 或独立转换服务。实现使用锁定 SDK 的 `upstream_adapter` v5，不修改宿主或 SDK

1. 在 CPR 新增 **OpenAI API Key** 账号，使用 `https://api.cline.bot/api/v1` 和 Cline API Key。按 CPR 现有方式配置公开模型到完整 Cline 上游模型的映射，并授予 Client Key 权限；插件不自动修改目录或权限
2. 打开「Cline 接入」，选择账号并点击「加入转换配置」，再点击「复制实例配置」。转换固定连接官方 `https://api.cline.bot/api/v1/chat/completions`，不使用账号地址重定向到其他站点；宿主注入该账号当前凭据并使用其代理
3. 先停用相关账号并排空请求。在插件管理中点击「CPR 数据工具箱」卡片右下角的设置按钮，弹窗内再点开设置按钮，在接下来的弹窗内粘贴已复制的 JSON（`clineAccountIds`）并保存。确认 `upstream_adapter` 的 `upstream` 绑定覆盖目标 Key、Provider 和模型，故障策略为 `reject`，然后恢复账号。页面的“当前实例已配置”表示冻结配置包含该账号，实际是否调用还取决于绑定、模型映射和权限
4. 在同页「DeepSeek 钉选」点击「添加规则」，选择同一上游账号，填写 CPR 映射后发给 Cline 的完整请求模型名称。允许的提供方默认 `deepseek`，能力过滤默认 `vision, implicit-caching`，可以修改或清空能力过滤。保存后按账号和请求模型名称匹配，不按下游 Client Key 区分。编辑时可修改请求模型名称，保存会替换原规则；与同账号的其他规则重名时拒绝覆盖。原有 1017 规则继续保留为普通可编辑规则

转换账号在发送 Chat 请求前直接应用钉选，无需另开 outbound / attempt 绑定。「请求模型名称」指发送正文的 `model`，不是上游返回的模型名称，也不是 CPR 映射前的客户端公开别名；未选择转换的账号保持原生执行。原有 Responses 反代仍可单独使用钉选，继续按原方式启用 `outbound`，观察实际来源还需 `attempt`

插件以保存的规则覆盖顶层 `provider` 和 `providerOptions.gateway` 路由条件：向两处写 `only/order`，`has` 只写入 gateway；其他 providerOptions 命名空间、消息和工具保留。提供方可按顺序填写多家，能力留空表示不注入能力过滤。未命中、停用或删除规则后，不改写该请求。最多 100 条规则，每条最多 8 个提供方及 8 项能力，配置上限 240 KiB，保存和删除使用私有状态版本比较

DeepSeek 1017 的组合依据 [ClinePassBridge v0.4.0 的 Chat Completions 对照实验](https://github.com/xiao-qiu-qiu/ClinePassBridge/blob/f8266a91540cfa8f56fe9884403adef9a35aa771/docs/upstream-capability-filter.md)。具体模型和订阅可用性以 Cline 当前账号为准，插件不调用推理接口自动探测

发送请求后，在同页点击「刷新日志」。转换直接读取 Chat 响应及 delta 中的 `provider_metadata.gateway.routing.finalProvider`（也识别 `providerMetadata`），并将元数据带回 Responses。「上游来源信息」显示这次请求实际回报的提供方，与已应用钉选一致时显示绿色；未钉选、来源不符或缺失时保持普通文字，缺失显示未知。未命中规则只显示「未命中」，日志不展示请求 ID 和尝试序号。来源不符不自动重放；提供方限制由 Cline 执行

支持 HTTP 流式与非流式 Responses、文本、图片 URL、函数工具及结果、完整历史、常用采样参数和 JSON 格式。SSE 按增量解析，保留文本、推理、工具、Token 用量和唯一终态；上游拒绝或缺少 `finish_reason` 的断流不会返回成功。单帧及累计生成内容限 512 KiB，单次工具最多 128 个，事件还受宿主分块容量约束。未返回的用量保持未知，费用由 CPR 按冻结模型定价计算

需要完整历史，不支持 `previous_response_id`、conversation、WebSocket、后台任务、响应存储、加密推理历史、文件引用和 OpenAI 原生/custom 工具；不支持的输入在发送前拒绝。推理摘要不冒充完整推理回灌，插件生成的明文 `reasoning_text` 可随历史转回 Chat。日志在内存保留 200 条，每页 25 条，不保存正文或凭据

转换账号选择先保存在草稿中，复制并应用到宿主实例配置后生效，单独重新启用实例不应用草稿。注册只读取握手中的冻结配置，不在私有状态尚未授权的安装阶段读取状态。移除前先停用依赖转换的账号，避免恢复原生路径后向 Cline 发送 `/responses`。钉选规则修改即时影响后续匹配请求；额度设置独立保留。目标宿主文本/工具往返、错误/断流、实际提供方和额度由用户验收

## 设置模型上游优先级

例如 A、B 都提供 `gpt-5.4`，在「模型上游优先级」点击「新增规则」，选择它们所属的 Provider，输入 `gpt-5.4`，点击「获取同名模型上游」。将 A 拖到第一位、B 放在第二位，保存规则后，在宿主为本插件启用 `scheduler`（账号调度）绑定，并选择需要生效的 Key 范围。空绑定范围表示全局；绑定建议采用失败时拒绝的策略，避免规则读取失败后改用原生调度

规则只在同一 Provider 内按完整上游模型 ID 精确匹配，区分大小写，不按显示名称、关键词或公开别名合并模型。列表也提供上移／下移按钮，第一位为首选，其余依次备用。输入模型时读取各账号模型目录，缺少或过期缓存时宿主可能查询上游；不发送推理请求。查询最多并发四个账号，整体期限 25 秒，单账号响应最多 1 MiB；单项失败会列出账号和原因。编辑已有规则时，查询未匹配或目录失败的旧账号保留原位置，新匹配账号追加到末尾

实际请求由宿主先按 Key 权限、模型黑白名单、账号状态和本次请求范围产生候选。插件只从当前可用候选中按顺序选择；首选繁忙、冷却或其他原因不可用时可选择后续账号。所有已排序账号都不可用时，交回宿主使用其他合法候选或原有等待逻辑，未列入顺序的新账号默认仍可备用。若不希望 B 承接此模型，请在「账号管理」中将该模型加入黑名单，而不是从优先级列表移除

连接失败后的换号仍受宿主重试预算和安全重放规则限制；原生续写要求的固定账号不能被本功能绕过，不对已经输出的流无条件重发。未配置、停用或删除规则的模型沿用宿主原有调度。规则使用账号 ID 关联，名称只用于展示；账号改名不影响顺序，删除或停用后不会强行调用。最多 100 条规则，每条最多 1000 个账号，配置整体不超过 240 KiB，保存和删除均通过私有状态版本比较避免覆盖并发修改

### 查看最近请求

在宿主为本插件启用 `observer` 的 `request_completed` 绑定，范围覆盖需要查看的请求。发送模型请求后，在「模型上游优先级 → 最近请求」点击「刷新日志」

表格分别显示每次尝试的插件选择、宿主完成事件中的最终上游、请求结果和尝试次数。「首选匹配」「备用匹配」表示最终上游与插件最后一次选择一致；交回原生调度、未命中规则、选择不一致或未发出请求会单独标注。只有调度记录、尚未收到完成事件时显示「等待完成观测」，不据此判断请求实际走向

日志在插件进程内存保留最近 200 条请求，每页 25 条，每条最多保留最近 32 次选择，可主动清空，重启后清空。同一次尝试的容量重选只保留最后决定。完成事件为有界实时投递，丢失时可能持续显示等待，不能作为完整历史账本；可按时间和请求模型名称对照宿主记录。内部关联 ID 保留，但页面不展示。日志不保存凭据、请求正文或上游错误正文

模型上游优先级与最近请求从 1.5 起提供，仅支持 RPC v7

## 查看上游额度

「上游额度」是默认打开的第一个标签页。在直接展示的「查询设置」中选择已有上游账号和查询平台，点击「保存并获取」。Kimi 的产品和地区在第三、第四列逐级选择，各级均支持搜索。每个账号独立保存查询类型和最近快照，默认不查询，不根据地址或模型自动识别上游。

- **CPR**：查询账号地址对应的 `/v1/quota`，使用 `schemaVersion: 1` 数组协议。上游也需安装并启用本插件，为此 API 秘钥（宿主 Client Key）开启额度分享；账号名称和模型列表由上游的分享设置决定，未分享时不推测。卡片直接显示上游已用百分比，点击「最后获取」时间右侧的「X 个模型」打开弹窗，实时搜索并点击复制模型名称
- **Kimi**：按量付费和编程订阅分别选择国内或海外，使用对应的官方查询地址。编程订阅分别显示短周期与周额度的已用进度，按量余额保留现金和代金券明细
- **DeepSeek**：查询账号地址的 `/user/balance`，分别显示 CNY、USD 余额；可用、赠送和充值余额同一行展示，可用余额加粗
- **Sub2API**：查询账号地址的 `/v1/usage`，显示钱包、Key 总额度、订阅及限额窗口，金额不换算成百分比
- **Command Code**：选择同名查询平台，沿用 CC Switch 的官方 `/alpha` 身份、credits、订阅与用量查询流程，自动带上组织及订阅周期范围。卡片显示五小时、周、月三项已用百分比，月额度按 CC Switch 的账期池口径计算，重置时间取订阅结束时间，不展示 credits 和本期费用明细。该控制面未公开文档化，接口变化可能需要同步适配
- **Cline Pass**：使用所选账号中保存的 **Cline API Key**，经账号受管 HTTP 查询 `https://api.cline.bot/api/v1/users/me/plan/usage-limits`，不能使用 CPA 或 CPR 的客户端 Key 代替。解析 `success/data/limits` 中的 `type`、`percentUsed` 和 `resetsAt`，显示 5 小时、周、月额度，未知窗口保留原名称，缺少比例或重置时间保持未知。超过 100% 的进度显示为 100%，仍标记已达限额；日历月不换算成固定秒数。不估算美元额度，不把模型名中的 DeepSeek 当作提供方证明

直连 Kimi、DeepSeek、Sub2API、Command Code 时，插件通过受管账号 HTTP 查询模型 ID，与余额共用一次查询期限并保存到私有快照。模型接口不支持或普通网络失败时保留余额；模型查询返回 401/403 时停止下传旧快照。CPR 模式仅显示上游已分享的逐账号模型，不从整站模型目录推测账号归属

Cline Pass 额度查询直接使用官方域名和账号当前代理，不访问模型推理接口。普通 `/models` 是 BYOK 目录，公开推荐目录也不能证明逐账号可用模型，因此该模式不填充模型目录。接口形态参考 [ClinePassBridge 的 usage 实现](https://github.com/xiao-qiu-qiu/ClinePassBridge/blob/f8266a91540cfa8f56fe9884403adef9a35aa771/internal/bridge/usage.go)，尚无公开稳定性保证，真实账号额度与网络链路需在目标宿主验收

「保存并获取」先保存插件设置，再等待首次查询结束。并发查询共用插件内的账号刷新锁，快照写入另用私有状态版本比较，防止覆盖并发设置。查询失败时仍保存设置并显示错误，保留同一凭据和查询类型的可用快照

打开插件时刷新一次，之后每三分钟按当前视图刷新，也可点击「刷新额度」立即查询。切换程序、浏览器标签或工具箱标签不会立即刷新；定时触发时页面不可见或不在「上游额度」标签则跳过，切回后等待下一轮，不补刷。关闭插件后清理定时器，已发送的请求仍可完成。查询设置有未保存的修改时暂停页面自动刷新。

插件通过 `maintenance` 在后台检查到期账号，不依赖页面定时器；CPR 和 Cline Pass 查询间隔一分钟，其他模式五分钟，每轮最多并发四个账号。手动查询至少间隔十秒，Kimi 编程订阅和 Command Code 至少十五秒；冷却期间禁用刷新按钮，沿用当前快照

刷新按钮左侧的「聚合」默认开启，展示全部启用且已配置查询的上游，不自动启用未配置的账号。关闭后在「额度详情」右侧下拉选择上游账号，只展示该上游的账号额度；切换选择只读取已有快照，不额外请求上游。卡片名称和来源标签分居两端，来源只显示账号名称，不显示 Key 内容；部分上游查询失败时，其他卡片和可用旧快照继续展示。

每个上游账号使用独立卡片，常规宽度下一行三列，窄屏缩为两列或一列。同一行卡片按内容最多的一张等高，超出上限后在卡片内部滚动。「额度详情」统一显示已用百分比，与宿主账号管理一致，透传也不转成剩余值。短周期和周额度并排，月额度排在底部并占满一行。模型详情弹窗使用组件默认位置，搜索框下方的模型 Tag 列表单独滚动，点击模型名称复制并显示通知。「最后获取」使用上游观测时间，界面时间按浏览器本地时区显示；未知额度保持未知，重置时间已过也不自动把百分比恢复。

未提供模型列表时显示「模型未提供」，只有确实返回空列表时显示「0 个模型」。原生 OpenAI credits 单独标为「额外点数余额」，不代表套餐窗口额度；没有金额、不为不限额且没有具体错误的空点数行不显示，旧快照也按此处理

查询失败保留同一凭据的旧快照，并显示错误和「数据过期」。更换账号 Key、切换查询类型或关闭查询后，不再使用旧凭据版本的快照。设置按插件私有状态版本条件更新，冲突时重新读取；查询前后复核宿主凭据版本，迟到结果不会覆盖新连接的快照

查询协议、快照、失败状态与分享设置均由插件持有，保存到 `host.state` 私有命名空间，不新增宿主业务表或账号字段。插件后端经二进制 RPC 读取账号凭据、构造请求，宿主只负责当前账号代理、受管网络和资源回收；凭据不进入页面、私有状态、控制元数据或日志，不改账号调度、健康和计费

CPR 查询期限五秒，Kimi 编程订阅与 Command Code 十五秒，其他模式十秒，包含模型获取；失败清理单独限时一秒。单来源展示快照限制为 240 KiB，以满足 `host.state` 单条 256 KiB 配额；超限保留可用旧快照并显示错误。下游响应上限为 1 MiB。金额按十进制原值展示，不补零或换算为百分比

### 向下游分享

上游 A 与下游 B 均安装并启用插件。A 为插件启用无 Key、账号或模型范围限制的 `http` 绑定，在「上游额度 → 向下游分享额度」选择 B 使用的 API 秘钥并开启分享；名称和模型默认不分享。B 为接入 A 的上游账号选择 CPR 查询，由插件后台获取并保存快照

`/v1/quota` 由插件 HTTP 中间件响应；未安装、停用或无匹配绑定时沿用宿主未知路由响应。插件调用 `verify_client` 验证入口身份，调用 `check_access` 检查账号与模型范围；宿主保持唯一授权权威。插件按每个 Key 的私有分享设置过滤内容，并使用独立随机命名空间生成匿名 ID。停用账号不导出，上游拒绝认证或权限后停止下传旧快照，成功获取后恢复。原生账号窗口只读取宿主已有 `quota_details` 事实

分享的模型是已取得目录与白名单、访问范围的交集，不会仅因勾选而增加上游未返回的模型。账号管理会保留已保存但未出现在当前目录中的 ID，这些勾选项不代表当前可用模型

开启模型分享后，原生 OAuth 账号通过公开宿主 HTTP 合同读取各自的模型目录，再逐模型检查该 Key 的访问权限。宿主缺少有效缓存时可能查询上游模型目录，不发送推理请求。单目录最多 1 MiB，一次分享的目录读取共用四秒预算；目录失败或超时时保留已有额度，通过可选 `modelsError` 字段向下游说明原因。关闭模型分享时，列表和错误说明一起移除

原生 OAuth 模型列表修复需要部署在分享方 A，只升级下游 B 无法补回上游未导出的列表。建议上下游同时升级，以显示完整的模型状态和目录错误

### SDK 来源

SDK 和打包 CLI 固定到 [CPR v3.33.0 的提交 `8c8618aa`](https://github.com/zyycn/codex-proxy-rs/commit/8c8618aa0f841638262262e3338c115bc075f125)。插件只使用公开 `gateway-plugin-sdk` 0.1.0，不依赖宿主内部模块

新增第三方查询类型只需修改插件。通用账号 HTTP、入口验证、授权检查与原生额度明细接口已随 CPR 3.33.0 发布

页面会检查所需接口，缺失时显示宿主升级提示和「重新检查」，分别禁用额度查询或分享操作；后台不会反复调用缺失的查询接口，其他标签页仍可使用。该提示适用于插件可启动的 RPC v7 宿主，RPC v6 及更早宿主不能启动本版本，应先升级宿主

## 配置模型 UA

安装并启用插件后，在 CPR 为本插件启用 `middleware` 的 `request` 绑定，建议限定到个人反代使用的 Client Key。空绑定范围表示全局；只保存规则但没有启用绑定，不会处理正常模型请求。

1. 打开「模型UA定制」，新增 `grok`、`gemini` 等包含规则并填写实际 UA
2. 将更具体的规则放在前面，保存后新请求使用新规则
3. 「匹配预览」检查当前编辑，「安全验证」选择 Key 并读取可见模型，检查已保存规则
4. 从客户端发送真实模型请求，再点击「请求改写日志」的「刷新日志」，检查是否进入插件以及使用了哪条规则

安全验证共用正式中间件的请求头改写逻辑，覆盖到插件请求出口，**不调用真实 `/v1/responses`，不发送上游推理请求**。它不覆盖真实入口鉴权、宿主绑定筛选、账号选择、默认画像组装和最终网络传输；模拟入口 UA 可选，留空时不推测真实 Key 默认 UA。最终 HTTP／WebSocket 出站头仍需在目标宿主确认。

### 用日志定位 UA 未生效

日志只记录实际进入 request 中间件的请求，预览与安全验证不产生记录。时间按浏览器本地时区以中文 24 小时格式显示，规则栏区分「已命中」「未命中」「模型缺失」「规则读取失败」；下游调用报错时额外显示「下游调用失败」。配套头发生变化时，前后 UA 栏直接展示 `originator`、`version`，不展示请求 ID。

改写前是插件入口头，不是宿主根据账号和 Key 画像生成的默认头；改写后是本插件交给宿主的头。如果日志显示「已命中」而上游仍收到其他 UA，应继续核对后续中间件和最终出站头。如果发送请求后刷新仍无记录，先检查插件启用状态、request 绑定和 Client Key 范围。

日志在插件进程内存保留最近 200 条，每页 25 条，可主动清空，重启后清空。只保存模型、请求关联 ID、规则及三个身份头，不保存 Authorization、Cookie、请求正文或 API Key；每个身份头最多采集 4096 字节，超出会标注「日志截断」，实际请求头不受日志截断影响。

## 导入来源与保存结果

1. 选择 CCS 完整 SQL 导出，在「API 导入」表格查看来源名称、应用和 API 地址
2. 点击 API 后的复制按钮可复制完整地址；Key 默认隐藏，点击眼睛查看，再次点击隐藏，旁边的复制按钮可直接复制 Key
3. 勾选来源或点击「全选」，再点击「一键接入 OpenAI Responses 兼容上游」；全选包含所有页，超过 100 个上游时按批顺序处理
4. 相同 API 与 Key 合并为一个上游，名称不同时在弹窗中选择；若匹配多个 CPR 账号，选择要更新的具体账号后确认接入

使用 CCS 的完整手动 SQL 导出，不使用云同步导出。当前适配 schema 20；未声明版本的导出须通过兼容结构检查。文件上限 64 MiB，按 256 KiB 分块上传；原始文件、临时 SQLite 库和解析结果只在后端内存暂存，闲置 15 分钟后清理，重启即清空。最多同时保留两个上传和两个解析来源，可点击「清理来源」提前释放。

0.3 补充 SQLite 创建索引所需的 `Reindex` 授权，仅限隔离内存库的 `main`；完整导出中的正常索引不再被该项白名单误拦，外部文件、附加数据库、扩展及其他未允许操作仍被拒绝。

预览只返回 Key 是否存在，主动查看或复制时才通过私有管理路由读取明文；管理响应禁用缓存，明文不写入日志或浏览器持久存储，隐藏、离开标签、重新预览、清理来源或完成接入后释放。接入直接使用来源地址，不改 API 路径或验证上游协议；缺少有效地址或 Key 的来源在表格中显示原因，OAuth 登录材料不能作为 Key 导入。

保存结果逐项显示；账号保存与来源映射不是同一事务，结果未知时停止后续项，先在宿主核对再重新预览，不自动重复创建。多个宿主账号匹配同组连接时必须选择具体宿主账号，其他账号不会被删除。

## 导入历史用量

1. 上传同一 CCS 安装的完整手动 SQL 导出，打开「用量导入」
2. 为该 CCS 安装填写固定来源标识，例如 `cc-switch`；不同安装使用不同标识
3. 核对「CCS 来源时区」，默认 `Asia/Shanghai`，可修改；日期解释、显示和时间范围均使用该时区，不取 CPR 服务器或浏览器时区
4. 选择应用（默认 Codex，可选全部），填写模型包含条件（默认 `gpt`，忽略大小写，清空不限）；模型匹配表格展示的模型，不改原始名称
5. 使用宿主同款日期时间选择器填写开始／结束时间，可单独清空任一边界，默认不限；按 CCS 记录的请求时间筛选，包含开始、不包含结束。三个条件同时应用于完整来源数据，再分页和汇总
6. 点击「预览导入变更」，确认来源及时间后点击「覆盖并导入」。覆盖会替换该时段内本来源的全部旧贡献，**不限旧贡献的应用和模型**，然后导入本次筛选结果；时间全部留空表示覆盖该来源的全部历史。「查看判重记录」仍可按需核对原生请求疑似重复项

使用完整手动导出作为只读来源，由插件筛选需要导入的记录。请求数据保留 CCS 原始秒级时间；日聚合使用来源日期的午夜，只有时间范围完整覆盖该来源日期时才纳入，部分覆盖的日期排除并说明，不能拆成小时用量。保留明细与日聚合日期交叠检查。CCS 新增输入转换为宿主含缓存输入，未知 Token 和费用不补零。来源费用是 CCS 原始 USD 记录，不代表供应商账单。

用量进入 CPR 原生总量、趋势与模型维度，不生成请求明细、账号、Provider、Key 或耗时样本。未映射的账号／Provider／Key 维度保持空值，相应筛选不包含这些贡献。

预览固定来源、时区、筛选条件和待执行变更；修改条件后旧预览失效，需要重新预览。已开始任务先继续或结束，再改变条件。每批最多 100 项，整批失败回滚，跨批次不是事务；暂停、超时或断线后点击「继续导入」核对同一快照的原批次。页面或进程重启后，使用同一来源标识重新上传完整导出并预览；稳定键覆盖不会重复累计。闲置任务 15 分钟过期，来源行数和贡献核对各限 200000 项。

筛选条件不进入记录键。覆盖范围按宿主旧贡献的 `bucket_start_ms` 归属时间判断，不要求还原旧记录的应用或粒度；同一范围内本次未选中的模型、应用及来源已不存在的旧记录也会清理。日聚合旧贡献整体归属来源日期午夜，不拆分到其他时刻。内容未变的贡献不重复写入，确认与原生请求重复的来源贡献不再导入。范围外贡献、CPR 原生请求和其他来源保持不变；选中记录已有范围外且内容不同的贡献时，扩大时间范围后再预览。没有符合条件的数据时不写入，也不清空该来源。

### 疑似重复的范围与限制

代理日志只对成功记录判重，CCS 代理日志记录时间与 CPR 完成时间相差不超过 30 秒，模型去除首尾空格后忽略大小写比较，不合并不同模型；含缓存输入与输出必须完全相同，双方有缓存数据时同时核对缓存读写。来源和 CPR 必须唯一对应，同一 CPR 请求不能排除多个 CCS 记录。当前完整来源中的未选中记录也参与候选冲突判断，防止换一个筛选范围就重复认领同一请求。

CCS 代理日志的 `created_at` 是写日志时的 UTC 秒，适合与 CPR 完成时间比较；会话日志采用各自事件时间，含义不同，保留并显示无法确认原因。[CCS 固定版本记录实现](https://github.com/farion1231/cc-switch/blob/99277921d9363c78e656ada0ca3bf39e30938b23/src-tauri/src/proxy/usage/logger.rs#L113)

当前公开 SDK 只按 CPR 开始时间筛选。插件按所选时间范围查询原生开始时段；未填的边界使用选中 CCS 记录的最早／最晚时间，再向前后各扩展 30 秒。逐页读取、不逐条查询、不扫描更早历史；每页 50 条、最多 200 页，超过容量要求缩小时间范围。比较仍使用实际完成时间，查询范围外更早开始的长请求不推断重复。日聚合、丢失原生明细的历史、未知时间／模型／Token、全零 Token、失败或未完成请求不自动排除。多候选保留，并提供前 20 条候选供核对。

用量导入与手动调整不修改 Key 预算。负修正不能超过归属时间桶的已有量，否则相应统计可能无法读取。停用插件不会撤销已经保存的账号、价格、统计贡献或历史费用。

## 筛选社区价目与历史费用选项

在「models.dev 社区价目」输入名称、模型 ID 或价格关键词，也可在「社区模型 ID」表头输入包含条件，点击「筛选」或按 Enter 应用。两项条件同时生效，忽略大小写，在整个选定来源中过滤后再分页；翻页保持已应用的条件，点击「清空筛选」恢复目录。

社区价目按钮右侧的「价格同步」打开历史费用同步弹窗，选择时间范围和 Provider，默认「只补全缺失费用」，已有 0 费用不视为缺失；另可选择覆盖范围内全部历史费用。每页扫描 50 条，只将能确定的 Token 估算费用写回；无法计价、缺少必要用量或包含图像的项显示跳过原因。覆盖会替换原费用并清除原计价快照，工具等附加费用不参与试算，Key 预算不变。CCS 导入的聚合贡献不参与费用重算。

可暂停后续页并继续当前范围。响应未确认时停止，不自动重发；继续时重新核对当前页，已确认数量不含未知结果。页面重载后需要重新选择范围，补全模式会保留已经写回的费用。

## 构建与打包入口

需要 Node.js 24 或更高、pnpm 12.6.0、Rust 1.99.1，以及宿主目标的 Rust target 和链接工具。前端 Git 依赖 `@codex-proxy/ui` 固定到 0.5.0 的提交 `5dec2c78fba37ee1f4c5007e4a0316837a72655a`，需要执行其构建脚本，已在 `web/pnpm-workspace.yaml` 明确允许；不要用 `--ignore-scripts` 安装后直接构建页面。

构建前确认宿主 target；开发电脑为 Windows 不代表宿主也是 Windows。

```powershell
pnpm --dir web install --frozen-lockfile
pnpm --dir web build
$target = Read-Host 'CPR 宿主的 Rust target'
cargo build --release --locked --target $target
```

打包 CLI 与 SDK 使用同一固定提交：

```powershell
cargo install --locked --git https://github.com/zyycn/codex-proxy-rs.git --rev 8c8618aa0f841638262262e3338c115bc075f125 codex-proxy-plugin-cli --root .tools/plugin-cli-v7
.tools/plugin-cli-v7/bin/cpr-plugin package --manifest plugin.json --binary "target/$target/release/cpr-data-toolkit" --target $target --resource-map web=web/dist --output-dir dist
```

该版本 CLI 支持 `x86_64-unknown-linux-gnu`、`aarch64-unknown-linux-gnu` 和 `aarch64-apple-darwin`，没有 Windows 原生包目标。资源映射将 `web/dist` 中的三个页面文件放入包内 `web/`；输出包位于 `dist/`。详见[固定版本打包合同](https://github.com/zyycn/codex-proxy-rs/blob/8c8618aa0f841638262262e3338c115bc075f125/backend/apps/plugin-cli/README.md)。

### 交付与版本递增

本次 1.9 仅交付 Linux ARM64，提供原生 `.tar.gz`、官方 CLI 生成的 `.sha256` 以及 ZIP。ZIP 内含对应原生包、校验文件和 `INSTALL.md`，解压后在 CPR 插件管理页上传 `.tar.gz`。其他平台本次未构建，安装说明见 `docs/installation.md`。

以后每次交付新包增加 `0.1`；打包前同步 `plugin.json`、`Cargo.toml`、`web/package.json` 和 Cargo 锁文件中的本项目版本。失败修复及同一次打包重试不重复递增，约定见 `AGENTS.md`。

多平台构建使用 `.github/workflows/package.yml`，在 GitHub Actions 手动运行「Build release packages」，选择待发布提交所在分支。工作流只构建产物，不自动发布；前端资源构建一次后供三个平台使用，Rust、SDK、CLI 和构建工具版本固定，Linux 使用 glibc 2.17 目标。下载对应构建产物后，通过 GitHub CLI 将安装包附到 Release。

实际发行物和已验证平台以对应 Release 附件与说明为准。RPC v7 安装、接口缺失提示和真实上游链路仍需在目标宿主验收
