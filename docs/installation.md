# 安装 CPR 数据工具箱

当前预发行版本为 **1.0**，CPR 内部版本为 `1.0.0`，清单兼容范围为 `>=3.29.8, <4.0.0`，使用 SDK 0.2.0 和 RPC v5。需要包含 [宿主 PR #505](https://github.com/zyycn/codex-proxy-rs/pull/505) 的宿主；SDK 与官方打包 CLI 固定到 [提交 `28799cc1`](https://github.com/KazeLiu/codex-proxy-rs/commit/28799cc150c6d5fe8288d3d8a0d83ba99b1407cf)。按 CPR 宿主进程的平台选择安装包，不按打开管理页的电脑平台选择。

上述宿主能力尚未正式发布，不要将 1.0 安装到正式版 v3.29.7。v3.29.7 继续使用插件 0.9，v3.29.0～v3.29.6 使用 0.8。

| 宿主平台 | 原生安装包 |
| --- | --- |
| Linux x86_64 | `kazeliu.cpr-data-toolkit-1.0.0-x86_64-unknown-linux-gnu.tar.gz` |
| Linux ARM64 | `kazeliu.cpr-data-toolkit-1.0.0-aarch64-unknown-linux-gnu.tar.gz` |
| macOS ARM64 | `kazeliu.cpr-data-toolkit-1.0.0-aarch64-apple-darwin.tar.gz` |

Linux 包需要 glibc 2.17 或更高，仅有 musl 的系统或容器不能直接运行。每个平台提供原生包、对应 `.sha256` 文件及 ZIP，下载入口为 [GitHub 预发行版 1.0](https://github.com/KazeLiu/cpr-data-toolkit/releases/tag/v1.0.0)；没有 Windows 正式包。

## 解压 ZIP 后上传安装包

1. 解压交付的 ZIP，保留其中的 `.tar.gz` 和 `.sha256` 文件
2. 在 CPR 插件管理页上传 `.tar.gz`，不要上传外层 ZIP，也不要把 ZIP 改名
3. 启用 `kazeliu.cpr-data-toolkit`，打开「CPR 数据工具箱」管理页

包内包含目标平台后端和已编译的页面，不需要在服务器安装 Node.js 或 Rust。插件以 `trustedProcess` 运行，与 CPR 使用同一系统身份。

## 查询与分享上游额度

1. 在「上游额度」选择已有 API Key 账号，明确选择 CPR、Kimi、DeepSeek 或 Sub2API 查询类型，点击「保存并获取」
2. 宿主使用该账号当前凭据和出站代理查询、保存并在后台定时刷新；「重新读取」不请求上游，「刷新额度」主动查询
3. 向下游分享时，上游与下游均安装并启用插件；上游启用插件 `middleware` 的 `request` 绑定，范围包含下游使用的 Client Key
4. 上游在「向下游分享额度」为该 Client Key 开启分享；账号名称和模型列表默认不分享，按需单独开启
5. 下游为接入上游的账号选择 CPR 查询，读取 `/v1/quota` 的授权快照

未安装、停用或绑定不匹配时，`/v1/quota` 返回 `404 quota_plugin_unavailable`。查询类型默认关闭，不自动识别；查询失败保留同一凭据版本旧快照并显示错误。认证或权限拒绝后停止下传旧快照，查询恢复后重新开放。余额保留原币种和十进制金额，未知值不补零。

## 让模型 UA 规则生效

1. 打开「模型UA定制」，新增模型包含关键词，例如 `grok` 或 `gemini`，填写要使用的 UA
2. 更具体的关键词排在前面，保存规则；忽略大小写，首条启用且命中的规则生效
3. 在宿主为插件启用 `middleware` 的 `request` 绑定，建议只选择个人反代使用的 Client Key；空绑定范围表示全局
4. 从客户端发送模型请求，点击「请求改写日志」的「刷新日志」，查看时间、模型、规则和替换前后 UA；配套头变化可展开查看

未命中时不改写身份头。`originator`、`version` 为可选配置，未填写的头保持原样。

「匹配预览」使用当前编辑，「安全验证」选择 Key 和可见模型，使用已保存规则。安全验证到插件出口为止，不调用真实 `/v1/responses` 或发送上游推理请求；最终出站头仍需在实际宿主配置下确认。

请求日志只记录实际进入插件中间件的请求，区分已改写、未命中、模型缺失和规则读取失败。替换前是插件入口 UA，不是 Key 默认画像；替换后是插件交给宿主的 UA。发送请求后刷新仍无记录时，先检查插件启用状态和 request 绑定范围。

日志在插件内存保留最近 200 条，每页 25 条，可主动清空，重启后清空；不记录认证头、Cookie、请求正文或 API Key。

## 导入与统计的边界

- API 导入使用 CCS 完整手动 SQL 导出，当前支持 schema 20 的 Claude、Codex 和 Gemini 配置，按来源地址与 Key 接入 OpenAI Responses 兼容上游，不按来源应用或协议拦截，也不自动改写 API 路径
- 表格可多选或跨页全选后一键接入；相同 API 与 Key 合并为一个上游，名称不同时在弹窗中选择，多个已有账号匹配时选定要更新的具体账号
- API 后的复制按钮复制完整地址；Key 默认隐藏，点击眼睛查看或点击旁边按钮复制，明文按需读取，不写入日志或浏览器持久存储
- 0.3 修正了完整 SQL 导出中创建索引被误拦截的问题，仍只在隔离内存库解析，不修改原始文件或宿主数据库
- 模型定价会写入 CPR 全局价目，影响后续估算，不重算历史费用；社区价目需核对实际模型 ID，缓存价格缺失或留空按零写入。社区表格支持名称、模型 ID 或价格关键词过滤，模型 ID 表头另有包含筛选，点击「筛选」或按 Enter 应用，先过滤整个来源再分页。价目表可全选筛选结果，社区和同步表可全选本页
- 「价格同步」按明确的时间范围与 Provider 试算并写回原生请求的 Token 费用，默认只补全缺失费用，0 费用不算缺失。覆盖会替换原费用和清除原计价快照，工具附加费不参与试算，不能确定的记录跳过
- 用量导入使用固定 CCS 来源标识，时区默认 Asia/Shanghai，可按来源修改；应用默认 Codex，模型默认包含 gpt，时间默认不限，使用宿主同款日期时间选择器。确认后替换该时段本来源的全部旧贡献，不限应用和模型，再导入筛选结果；时间全部留空表示本来源全部历史。时段外贡献、CPR 原生请求和其他来源保留，空筛选结果不清理。疑似重复仅排除唯一对应的代理明细；日聚合须完整覆盖来源日期，详细规则见 README「导入历史用量」
- CCS 用量以统计贡献进入原生总量、趋势与模型维度，不生成请求列表，未映射的账号／Provider／Key 筛选不包含它，不新增耗时样本；手动调整归属首次提交时刻，仅增减 Token 与请求总量，两者均不改变 Key 预算
- 导入每批 100 项，可暂停并继续；任务闲置 15 分钟过期，重启后以同一来源标识重新上传完整文件恢复。手动调整结果未确认时保留操作 ID，重新打开页面继续核对，不另建相同修正
- 账号保存结果未知时先核对宿主，不直接重复创建；停用插件不会自动撤销已经保存的账号、价格、统计贡献或历史费用

本次打包不包含服务器安装或真实数据验收。
