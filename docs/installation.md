# 安装 CPR 数据工具箱

当前版本为 **2.9**，内部版本 `2.9.0`，要求 CPR **3.40.0 或更新的兼容版本**，使用 RPC v7、公开 SDK 0.1.0、upstream_adapter v5 和 middleware v6。SDK 与打包 CLI 固定到 [CPR v3.40.0 的提交 `789609dd`](https://github.com/zyycn/codex-proxy-rs/commit/789609dd53663b323e43567d2476f7f83b6b77a1)

从 [2.9 Release](https://github.com/KazeLiu/cpr-data-toolkit/releases/tag/v2.9.0)下载对应平台的 `.tar.gz` 和 `.sha256`，或下载 ZIP 后解压。通过宿主 GitHub 来源安装时，仓库填写 `KazeLiu/cpr-data-toolkit`，标签填写 `v2.9.0`

## 在原插件实例上升级

先升级宿主至 3.40.0 或更新兼容版本，再在原插件实例升级到 `v2.9.0`，不要卸载或清空状态。升级前保留常规宿主备份，升级后关闭再打开插件管理页

2.9 的模型列表替换默认关闭，已有转换账号与钉选规则不受影响。开启后须在第 3 步复制配置，并到插件设置粘贴保存。区域筛选参数在「转换与钉选日志 → 详情」查看，列表不再单独显示区域提示

2.3 更新全部标签页样式与界面文案，沿用现有主题、配置和状态结构，见 [发布说明](releases/2.3.md)

2.2 改用宿主聚合快照，按模型、Key 和请求历史路由分组统计，见 [统计说明](statistics.md)。UA 功能需要启用 `outbound` 绑定并置于出站链最外层，原有 `request` 绑定继续用于下游模型权限

旧 CPR 查询设置在本版本中按「不查询」读取，停止刷新、展示和转发对应快照；原始状态保留，不改账号凭据，不自动开启宿主互联。其他平台查询、分享设置和状态 schema 保持不变

1.7.1 扩展了上游额度状态中的查询类型，却未声明状态迁移，导致从 1.6.1 升级时被宿主拒绝。1.7.2 将 `upstream_quota` schema 升为 2，声明从 schema 1 迁移，并逐项原样保留键和值；记录版本和状态提交由宿主管理。已有查询设置、额度快照和其他命名空间中的配置原样保留，不修改账号凭据和 `/v1/quota` 的 `schemaVersion: 1` 协议

1.8.1 保留该迁移及所有已有状态 schema，新增独立的 `cline_adapter` 命名空间。Cline 转换默认不接管任何账号，升级不会自动改变原有路由；需要此功能时按下文配置

迁移由宿主分批校验和事务提交，失败时不通过插件删除旧状态。若仍遇到升级错误，保留原实例并记录宿主版本和错误详情，不以清库或重装绕过

额度功能所需的账号 HTTP、入口认证、授权检查和原生额度接口已包含在 CPR 3.33.0 中。接口缺失时页面会提示升级，分别禁用受影响的查询或分享操作，点击「重新检查」可再次检测；其他标签页不受影响。旧版本安装附件不再提供，源码与 Git 标签保留；RPC v6 及更早宿主应先升级

按 CPR 宿主进程的平台选择 Linux x86_64、Linux ARM64 或 macOS ARM64 构建目标，不按打开管理页的电脑平台选择。Linux 目标为 glibc 2.17 或更高；仅有 musl 的系统或容器不能直接运行，没有 Windows 正式包

曾使用 #505 实验宿主的环境，应保留原分支与实验数据库备份，不把实验迁移直接套到主线数据库。查询类型和分享设置需在本插件中重新配置；插件不会读取实验宿主专表或搬运真实凭据

## 解压 ZIP 后上传安装包

1. 解压交付的 ZIP，保留其中的 `.tar.gz` 和 `.sha256` 文件
2. 在 CPR 插件管理页上传 `.tar.gz`，不要上传外层 ZIP，也不要把 ZIP 改名
3. 启用 `kazeliu.cpr-data-toolkit`，打开「CPR 数据工具箱」管理页

包内包含目标平台后端和已编译的页面，不需要在服务器安装 Node.js 或 Rust。插件以 `trustedProcess` 运行，与 CPR 使用同一系统身份。

## 查询与分享上游额度

1. 在「上游额度」选择已有API密钥账号，明确选择 Kimi、DeepSeek、Sub2API、Command Code 或 Cline Pass 查询类型，点击「保存并获取」
2. 插件后端读取账号当前凭据，通过宿主的账号受管 HTTP 使用当前代理查询；配置和快照保存在插件私有状态，`maintenance` 在页面关闭后继续检查到期刷新
3. 保留旧协议分享时，在分享方启用插件 `middleware` 的 `http` 绑定，清空该绑定的API密钥、账号和模型范围限制。入口先于数据面认证，访问控制由插件随后调用宿主认证与授权接口执行
4. 上游在「额度分享」为该API密钥开启分享；账号名称和模型列表默认不分享，按需单独开启
5. 下游使用支持插件 `schemaVersion: 1` 协议的客户端读取 `/v1/quota`，例如 1.9 或更早版本插件；2.0 不再提供该查询类型

CPR 上游额度改用宿主原生 CPR Link：上游管理员在给当前连接使用的API密钥中开启「CPR 互联」，选择账号分组，需要池内窗口时勾选「共享账号额度」；本机在「账号管理」展开该上游账号查看「上游额度」。两端宿主均需支持当前互联协议，插件最低宿主版本不代表该宿主已支持 CPR Link。开启互联会将该 Key 的推理限制到分组内直连账号，建议使用独立互联 Key

未安装、停用或绑定不匹配时，`/v1/quota` 沿用宿主未知路由响应。查询类型和分享均默认关闭，不自动识别；查询失败保留同一凭据及查询类型的旧快照并显示错误。认证或权限拒绝后停止下传旧快照，查询恢复后重新开放。余额保留原币种和十进制金额，未知值不补零

插件单来源展示快照上限 240 KiB，分享响应上限 1 MiB。私有状态按实例隔离，卸载或更换实例不会自动接管另一实例的查询设置、快照或分享开关

分享原生 OAuth 账号的模型时，上游分享方需更新到 1.6。插件读取逐账号目录后再按API密钥权限过滤；只更新下游不会补回上游缺失的模型。建议上下游同时升级。目录读取失败时保留额度并显示原因；「模型未提供」与确实为空的「0 个模型」分别显示

「额外点数余额」与 5 小时、周套餐窗口相互独立。没有有效余额数据的空点数行不显示，不将无额外点数解释为整个账号额度不可用

开启「账号名称」后统一分享当前 CPR 账号管理中的名称，不使用邮箱。改名后下游下次成功查询生效；默认名称「OpenAI 账号」需在账号管理中自行修改。关闭名称分享仍使用匿名编号

当前源码的 Cline Pass 模式使用账号中的 Cline API密钥查询官方 `usage-limits`，显示上游已用比例和重置时间，每分钟后台检查刷新，不提供金额估计或账号模型目录。经 CPA 调用模型不意味着 CPA 的客户端API密钥能查询 Cline 官方额度；需要单独配置保存 Cline API密钥的账号。原有凭据版本检查、失败快照和分享权限继续生效

## 配置下游模型权限

1. 打开「下游模型权限」，选择API密钥，开启「限制模型」
2. 获取模型列表并勾选允许的下游模型 ID，点击「保存权限」；启用后白名单为空表示全部禁止，保存前会确认
3. 在宿主启用本插件的 `request` 绑定，API密钥范围留空或包含目标API密钥，账号范围留空，失败策略选择「拒绝请求」

白名单只收紧宿主原有权限，模型 ID 区分大小写，别名按客户端使用的名称配置。普通和 Codex 模型目录、模型详情及模型请求使用同一份白名单，未授权请求返回 403。关闭限制恢复宿主原有权限并保留勾选内容。目录读取失败不清空白名单，保存冲突时需重新读取后确认

受限API密钥的模型身份无法确定时拒绝请求，包括当前无法取得模型身份的 multipart 图片编辑。`/v1/quota` 仅披露白名单中的模型原名，别名对应的实际下游目录以 `/v1/models` 为准。停用插件或未命中绑定时，插件权限规则不生效

## 在同一页启用 Cline 转换与 DeepSeek 钉选

本包包含 Cline 协议转换、DeepSeek 钉选和 Cline Pass 查询。锁定 SDK 已提供 upstream_adapter v5，无需修改 SDK 或宿主

1.8.1 移除 1017 预设入口，原有规则保留为普通可编辑规则；各标签页直接展示内容，不再提供折叠入口

1. 在 CPR 新增 OpenAI API密钥账号，填入 `https://api.cline.bot/api/v1` 和 Cline API密钥；按现有方式配置 Cline 模型映射及下游API密钥权限
2. 在「Cline 接入」选择已有账号，点击「加入转换配置」。需要替换模型列表时先打开第 2 步的开关，再到第 3 步点击「复制实例配置」。账号只提供凭据和代理，转换固定调用官方 Chat Completions 端点
3. 先停用相关账号并排空请求。在插件管理中点击「CPR 数据工具箱」卡片右下角的设置按钮，弹窗内再点开设置按钮，在接下来的弹窗内粘贴已复制的 JSON（`clineAccountIds` 数组）并保存。启用插件 `upstream_adapter` 的 `upstream` 绑定，Provider 为 `openai`，覆盖目标API密钥 和模型，故障策略使用 `reject`，然后恢复账号
4. 在同一 Tab 的「DeepSeek 钉选」点击「添加规则」，选择上游账号，填写 CPR 映射后发送正文 `model` 中的请求模型名称。提供方默认 `deepseek`，能力默认 `vision, implicit-caching`，均可修改。规则只影响选中账号的这个请求模型，不按下游 API密钥 区分。编辑时可修改请求模型名称，保存后替换原规则，不覆盖其他同名规则；原有 1017 规则保留
5. 下游继续调用 CPR 的 Responses 地址并使用 CPR API密钥。发送后在同页刷新日志查看参数和「上游来源信息」；来源与钉选一致时显示绿色，未回报时显示未知，未命中规则显示「未命中」

转换账号直接应用钉选并观察 Chat 元数据，不需要 outbound / attempt。原有 Responses 反代仍按原方式启用这两个绑定。规则不改变 CPR 调度；转换支持 HTTP 完整历史、文本、图片 URL、函数工具及 JSON / SSE 响应，不支持原生续接、加密历史或 WebSocket。日志最多 200 条，不记录正文或凭据，来源不符会提示，不自动重试

转换账号选择保存在页面草稿中，实际注册范围来自宿主实例配置；只重新启用实例不会应用草稿。钉选规则即时影响新请求。安装前保留当前安装包；升级或回退前先停用依赖转换的 Cline 账号并排空请求，确认新实例与 upstream 绑定后再恢复账号。真实宿主链路由用户验收，不支持 WebSocket、原生续接、加密推理历史、文件引用或 OpenAI 原生/custom 工具

要替换下游目录，在「协议转换 → 2 · 模型列表替换」打开开关，插件读取整个 ClinePass 官方目录。到「3 · 应用实例配置」复制配置，再到插件设置粘贴。保存前在「高级设置」启用「上游调用」，只填 Provider 范围 `openai` 以发布目录；启用「请求开始」，只选下游拉取目录用的 API密钥以隐藏旧模型。保存后刷新下游列表；已有模型白名单仍需放行所用的完整 `cline-pass/` ID。

原模型、映射到原模型的别名和其他账号的同名条目都会从下游列表隐藏。要刷新已开启的目录，点「生成目录配置」后复制并保存；关闭开关并保存后恢复原目录。

## 让模型上游优先级生效

自 1.5 起提供模型上游优先级、顺序备用与最近请求查看

1. 打开「模型上游优先级」，新增规则，选择 Provider 和完整上游模型名称，获取同名模型账号
2. 拖拽或使用上移／下移调整顺序，第一位首选，其余按顺序备用，保存规则
3. 在宿主为本插件启用 `scheduler`（账号调度）绑定，限定到需要使用的API密钥；建议失败策略设为拒绝，避免规则不可读时继续原生调度
4. 启用 `observer` 的 `request_completed` 绑定，范围覆盖同一批请求；发送模型请求后，在「最近请求」点击「刷新日志」，对照插件选择与最终上游，查看首选／备用是否匹配

宿主权限、模型黑名单、账号状态、续写固定账号和重试限制继续生效。其他合法候选默认保留备用资格，不需要的备用请在「账号管理」将该模型加入黑名单。保存规则但没有启用匹配的账号调度绑定时，不会改变请求选择

最终上游只取宿主完成事件；缺少观测时显示等待，不将调度选择当作实际发送结果。完成事件可能因有界投递而丢失，可按时间和请求模型名称核对宿主记录。页面不展示请求 ID，内部关联保留。最近请求在插件内存保留 200 条，每页 25 条，每条最多保留 32 次选择，清空或重启后释放，不记录凭据及请求正文

## 让模型 UA 规则生效

1. 打开「模型UA定制」，新增模型包含关键词，例如 `grok` 或 `gemini`，填写要使用的 UA
2. 更具体的关键词排在前面，保存规则；忽略大小写，首条启用且命中的规则生效
3. 在宿主为插件启用 `middleware` 的 `outbound` 绑定，放在出站链最外层，避免外层插件再次覆盖；建议限定API密钥范围
4. 从客户端发送模型请求，在「请求改写日志」刷新，查看出站模型、规则及宿主画像生成后的改写前 UA、交给传输层的改写后 UA

未命中时不改写身份头。`originator`、`version` 为可选配置，未填写的头保持原样。

「匹配预览」使用当前编辑，「规则验证」选择API密钥和可见模型，使用已保存规则试算，不进行真实推理，也不还原路由映射和宿主画像。实际出站头在目标宿主确认。

日志只记录原生出站准备，每次重试分别记录。改写前取宿主已处理的头，改写后取本插件完成出站链及规则改写后返回的头；失败时不生成改写后值。Cline 转换独立保留 UA 规则，不生成原生画像日志。无日志时检查 outbound 绑定范围。

日志在插件内存保留最近 200 条，每页 25 条，可主动清空，重启后清空；不记录认证头、Cookie、请求正文或API密钥。

## 导入与统计的边界

- API密钥导入使用 CCS 完整手动 SQL 导出，当前支持 schema 20 的 Claude、Codex 和 Gemini 配置，按来源地址与API密钥接入 OpenAI Responses 兼容上游，不按来源应用或协议拦截，也不自动改写 API 路径
- 表格可多选或跨页全选后一键接入；相同 API 与API密钥合并为一个上游，名称不同时在弹窗中选择，多个已有账号匹配时选定要更新的具体账号
- API 后的复制按钮复制完整地址；API密钥默认隐藏，点击眼睛查看或点击旁边按钮复制，明文按需读取，不写入日志或浏览器持久存储
- 0.3 修正了完整 SQL 导出中创建索引被误拦截的问题，仍只在隔离内存库解析，不修改原始文件或宿主数据库
- 模型批量定价会写入 CPR 全局价目，影响后续估算，不重算历史费用；社区价目需核对实际模型 ID，缓存价格缺失或留空按零写入。社区表格支持名称、模型 ID 或价格关键词过滤，模型 ID 表头另有包含筛选，点击「筛选」或按 Enter 应用，先过滤整个来源再分页。价目表可全选筛选结果，社区和同步表可全选本页
- 「同步历史费用」按明确的时间范围与 Provider 试算并写回原生请求的 Token 费用，默认只补全缺失费用，0 费用不算缺失。覆盖会替换原费用和清除原计价快照，工具附加费不参与试算，不能确定的记录跳过
- CC-Switch用量导入使用固定 CCS 来源标识，时区默认 Asia/Shanghai，可按来源修改；应用默认 Codex，模型默认包含 gpt，时间默认不限，使用宿主同款日期时间选择器。确认后替换该时段本来源的全部旧贡献，不限应用和模型，再导入筛选结果；时间全部留空表示本来源全部历史。时段外贡献、CPR 原生请求和其他来源保留，空筛选结果不清理。疑似重复仅排除唯一对应的代理明细；日聚合须完整覆盖来源日期，详细规则见 README「导入历史用量」
- CCS 用量以统计贡献进入原生总量、趋势与模型维度，不生成请求列表，未映射的账号／Provider／API密钥筛选不包含它，不新增耗时样本；用量调整归属首次提交时刻，仅增减 Token 与请求总量，两者均不改变API密钥预算
- 导入每批 100 项，可暂停并继续；任务闲置 15 分钟过期，重启后以同一来源标识重新上传完整文件恢复。用量调整结果未确认时保留操作 ID，重新打开页面继续核对，不另建相同修正
- 账号保存结果未知时先核对宿主，不直接重复创建；停用插件不会自动撤销已经保存的账号、价格、统计贡献或历史费用

服务器安装、接口缺失提示、真实数据和 RPC v7 链路仍需在目标宿主验收
