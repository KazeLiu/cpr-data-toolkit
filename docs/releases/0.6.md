# CPR 数据工具箱 0.6

内部版本 `0.6.0`，最低宿主 CPR v3.29.0。SDK 与官方打包 CLI 固定到 v3.29.4，升级到 RPC v4、management v2 和 middleware v5

## 现在可以写入原生用量

- **用量导入**：读取 CCS 完整手动 SQL 导出，按原有有效用量规则去重、归一缓存语义，保留来源时间、模型与原始 USD 费用，以统计贡献写入 CPR 原生总量与趋势
- **快照替换**：同一 CCS 安装始终使用相同来源标识，新完整导出替换该来源的旧贡献，相同记录不会重复累计。明确来源 IANA 时区，明细与日聚合日期交叠时拒绝导入
- **分批恢复**：每批最多 100 项，可暂停、继续或结束任务。结束任务不撤销已写入贡献；重启或过期后使用同一来源标识重新上传完整导出恢复
- **手动调整**：Token 与请求数正负增减真实生效，归属首次提交时刻；负修正按归属 15 分钟桶的真实原值限制，操作 ID 和状态支持结果未确认后的继续核对
- **历史费用同步**：选择时间范围和 Provider，逐页补全缺失费用或覆盖范围内历史费用。已知零费用不算缺失，无法计价的记录显示跳过原因

API 导入、全局价目维护、社区价目筛选、UA 规则及请求日志保留。来源材料只在受限后端内存中解析，不修改源文件或来源应用配置，不直接访问宿主数据库

## 安装与使用

提供 Linux ARM64 和 Linux x86_64 包，按 CPR 宿主进程的平台选择。ZIP 解压后上传其中的 `.tar.gz`，安装说明见 `docs/installation.md`

导入前保留 CCS 完整导出，为该安装填写固定来源标识和真实来源时区，例如 `cc-switch`、`Asia/Shanghai`。不要使用部分导出替换完整历史，不要把不同 CCS 安装共用一个标识；与 CPR 自身请求的跨系统重叠须自行核对

## 数据边界

- CCS 用量不生成虚构请求列表、延迟样本或账号／Provider／Key 映射，缺失维度不会参与相应筛选
- 导入和手动调整不改变 Key 预算；停用插件不撤销已经保存的数据
- 历史费用写回只计算 Token 费用，覆盖会替换原费用并清除原计价快照，不计算工具等附加费，不处理 CCS 聚合贡献
- 分批写入不是跨批次事务，中断期间统计可能不完整；保留当前任务继续，或重新准备同一来源完整快照

构建和安装包检查记录见 `docs/usage-integration-plan.md`。本次不安装插件、不写真实用量；来源总量、原生页面展示及重复导入由用户安装后验收
