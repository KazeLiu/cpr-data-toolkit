# CPR 数据工具箱 0.9

内部版本 `0.9.0`，最低宿主 **CPR v3.29.7**，兼容范围 `>=3.29.7, <4.0.0`。SDK 和官方打包 CLI 固定到 v3.29.7 提交 `78bc57c5cf24b01a38e985cdd739bb4ae89ce11f`，使用 RPC v5

## 升级安装

先升级 CPR 到 v3.29.7，再上传对应平台的 0.9 原生 `.tar.gz`。旧版 0.8 使用 RPC v4，不能继续配合新版宿主；0.9 不支持 v3.29.6 或更早的宿主。插件身份、私有状态 schema 和业务功能保持不变，无需重新导入数据或重建 UA 规则

- Linux ARM64：`kazeliu.cpr-data-toolkit-0.9.0-aarch64-unknown-linux-gnu.tar.gz`
- Linux x86_64：`kazeliu.cpr-data-toolkit-0.9.0-x86_64-unknown-linux-gnu.tar.gz`
- ZIP 内含原生包、官方 `.sha256` 和 `INSTALL.md`，解压后向 CPR 上传 `.tar.gz`，不要上传 ZIP
- Linux 需要 glibc 2.17 或更高，本地产物位于 `dist/0.9/`

## SDK 升级与接口核对

- 使用新 SDK 重新编译后端，并用同一提交的官方 CLI 重新打包；不是仅修改清单版本
- `management` v2 和 `middleware` v5 未变，继续只注册这两项能力，不新增 `upstream_adapter`
- UA 中间件、预览和管理响应已使用字节头；继续通过 SDK 的增量接口改写指定身份头，其余头和下游响应原样交回 SDK
- models.dev 查询继续使用受管 HTTP：请求头采用 SDK 新的字节值类型，响应的 HTTP 版本与尾部头由新 SDK 解码，业务仍只读取状态和 JSON 正文
- 本插件不构造模型响应元数据、WebSocket 原文或上游适配器事件，无需迁移 `UpstreamAdapterEvent.service_tier`；历史费用复算使用的 `UsagePricingInput.service_tier` 合同未变，保留原有计价档位
- CI 同步固定新 SDK／CLI 提交，前端 UI 依赖保持不变

升级依据：[宿主 v3.29.7 发布说明](https://github.com/zyycn/codex-proxy-rs/releases/tag/v3.29.7)、[受管 HTTP 与模型调用合同](https://github.com/zyycn/codex-proxy-rs/blob/78bc57c5cf24b01a38e985cdd739bb4ae89ce11f/backend/crates/gateway-plugin/sdk/docs/capabilities.md)、[上游适配器合同](https://github.com/zyycn/codex-proxy-rs/blob/78bc57c5cf24b01a38e985cdd739bb4ae89ce11f/backend/crates/gateway-plugin/sdk/docs/upstream-adapters.md)
