# 下游模型权限

在工具箱的「下游模型权限」标签页选择API密钥，开启「限制模型」，勾选允许使用的下游模型 ID 后保存。关闭限制会恢复宿主原有权限，保留白名单供再次启用。启用限制但不选择模型表示全部禁止，保存前会再次确认。

## 生效条件

- 宿主启用本插件及其 `request` 绑定，API密钥范围留空或包含目标API密钥，账号范围留空，以覆盖模型目录查询；失败策略选择「拒绝请求」，防止插件故障时跳过权限检查
- 规则按下游公开模型 ID 精确匹配、区分大小写；模型别名也按下游请求使用的别名配置
- 最终权限是宿主原有权限与白名单的交集，不改变分组、上游账号选择、模型映射或预算
- 没有规则或关闭限制的API密钥保持原有行为
- 插件停用、卸载或未命中绑定时，插件规则不生效

## 实现与验收标准

1. `src/key_models.rs` 通过公开 `host.state.*` 按API密钥保存 `{ enabled, models }`，使用精确版本防止并发覆盖；管理路由检查API密钥存在，不读取API密钥明文
2. `src/main.rs` 的 request 入口先检查白名单，再沿用模型 UA 逻辑；未授权模型返回 403，不进入上游调用；用量等无模型只读查询保持原行为。优先使用宿主模型身份，原生 JSON 端点读取正文 `model`；宿主和正文均无法确定模型时拒绝受限API密钥的请求，包括缺少 `model` 的原生请求和宿主尚未提供模型身份的 multipart 图片编辑
3. `/v1/models` 只过滤宿主成功响应，保留模型元数据与顺序；支持 OpenAI `data[].id` 和 Codex `models[].slug`；模型详情同样受限
   `/v1/quota` 额度分享中的模型 ID 也按白名单收紧；快照只提供上游原名而白名单使用别名时，不披露该原名，实际下游目录以 `/v1/models` 为准
4. `web/src/features/KeyModels.vue` 复用宿主组件，提供API密钥选择、可搜索的模型勾选列表、未在目录中的已选模型保留、保存和恢复已保存内容
5. 目录获取失败不清空已保存的白名单，不允许把读取失败当作未配置；状态读取失败时请求失败，不放宽权限

## 验证范围

开发阶段按用户约定只进行代码、调用链和差异自查；1.7.1 发行构建与产物记录见 [1.7.1 发布说明](releases/1.7.1.md)。不新增或运行测试，不启动应用或浏览器。

目标宿主验收时分别核对：未配置API密钥不变；已选模型正常请求；手工指定未选模型返回 403；普通与带 `client_version` 的模型列表只含白名单交集；禁用限制恢复原目录；空白名单全部禁止；并发保存冲突不会覆盖另一份配置。HTTP、SSE 和 Responses WebSocket 的模型请求都应命中 request 绑定。
