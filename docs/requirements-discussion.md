# CPR 数据工具箱：历史数据补入与维护

记录日期：2026-10-12。项目名称为 CPR 数据工具箱，标识为 `cpr-data-toolkit`，开发目录为 `D:\Code\cpr-data-toolkit`。CC Switch 是首个明确的导入来源，插件能力不限定为 CCS 专用。

## 用户明确的四项需求

管理页面使用四个标签，标题与职责已按用户要求收敛如下：

| 标签标题 | 职责 |
| --- | --- |
| API 导入 | 首先接入 CCS 的站点配置，预览、去重并导入 CPR 账号管理 |
| 用量导入 | 首先接入 CCS 的历史 token 计数和请求统计，去重后补入 CPR |
| 手动调整 | 填写 token 和请求次数的增减量，预览变更并在提交前提醒统计指标可能不一致 |
| 模型定价 | 同步模型价目，批量新增、修改和删除价格，并使其对 CPR 的计价生效 |

四个标签分别承载这四项功能，不增加用量分析标签。价格同步和批量维护在“模型定价”标签内完成；前两个标签当前支持 CCS，来源适配保留扩展空间。

### 1. 导入去重后的历史用量

使用场景：之前使用 CC Switch 连接中转站，历史统计保存在 CCS；切换到 CPR 直连后，保留过去的统计信息并补入 CPR。

目标按补入 CPR 原有统计理解，展示沿用 CPR 的统计视图；插件负责导入与维护。需处理来源内部重复和重复导入，保留可用的历史时间、账号/站点、模型、token 分类、请求次数及原始统计口径。

去重至少涉及：同一文件重复导入、来源内代理和会话记录重复、导入日期与 CPR 已有记录交叠。不能把相似 token 数和相近时间直接当作跨系统请求身份一致的证明。

### 2. 手动增减 token 与请求次数

允许补录遗漏量或减去错误量。用户已选择首版简化方案：填写 token 与请求次数的增减量，不要求提供模型、费用或逐请求耗时，提交前弹窗提醒派生指标可能与调整后的总量不一致。

首版交互：输入增减量 → 显示本次变更及调整后的数字 → 弹窗提醒 → 用户确认后提交。弹窗按钮为“取消”和“确认调整”，界面文案遵守宿主短语约定。

建议的弹窗文案：

> 手动调整仅修改 Token 与请求总量
>
> 未提供模型、费用和耗时信息，总计费、首字均值等指标无法随补录量完整更新，可能与调整后的总量不一致
>
> 请确认填写的数字后继续

这里的“不一致”指手动补录缺少明细，不能据此补齐费用或性能观测，并非断言每个已有均值必然计算错误。首版不根据手填总量猜测模型、费用、耗时或成功/失败分类，也不尝试通过假造请求明细补齐指标。

实现时仍需核对 CPR 的统计接口如何接纳修正量，以及原有指标在修正后的表现。缺失耗时不能填成零混入均值，未知费用不能等同于免费；如果现有计算口径会受影响，应在弹窗明确列出实际影响。每请求平均 token 若按修正后总 token / 总请求数计算，分母为零时无平均值。

建议保留手动修正记录及撤销能力，便于发现填错数字后恢复；具体日期、账号归属、token 分类字段及减量边界仍待界面设计讨论。

### 3. CCS 站点连接导入 CPR 账号管理

将 CCS 保存的站点名称、上游地址、API Key 及必要协议配置映射为 CPR 账号，导入结果进入 CPR 自带账号管理。支持预览、选择、去重和逐项结果，协议不兼容时说明原因。

来源适配层可扩展；不同来源复用统一导入流程与 CPR 账号写入路径。

### 4. 模型定价同步与批量维护

目的：OpenAI 兼容接口可能提供 GPT 以外的模型，需要批量新增、修改、删除和同步模型价格，并使其对 CPR 的计价生效。

已核对 v3.25.0 的公开 API 合同：

- 价目键为 Provider 与精确上游模型 ID，Provider 为 `openai` / `xai`
- 更新允许非内置模型；未在内置或同步价目中登记的模型需要提供 standard 价格
- 同一请求可更新 1～500 个模型；该请求的 change 是统一操作，不等于一个请求内任意逐行不同价格
- 删除不适用于内置模型；内置模型可重置人工覆盖
- models.dev 的现成同步限定 OpenAI/xAI，其他模型来源需要另外映射
- 改价影响后续本地估算和相应限额，不自动重算历史费用

依据：[CPR 模型定价合同](https://github.com/zyycn/codex-proxy-rs/blob/05ba116eef849a0f4fa2d1940be82182bb2f7683/docs/api.md#模型定价)

## 当前需要决定的口径

1. 同一模型的价格沿用 CPR 当前全局价目，还是需要各中转站/账号独立价格
2. 手动修正的日期、账号归属、token 分类与减量边界；首版已确定允许无模型的数字增减，并在提交前提醒指标不一致
3. 导入 CCS 明细与日聚合的粒度，以及未知账号/模型如何映射
4. 模型价目同步来源、模型 ID/别名映射和历史费用是否保持原值

## 实现前仍需核对

用户运行的 CPR 与 CCS 版本、宿主部署位置尚未核实。2026-10-12 进一步核对已确认账号保存与模型定价均有插件可用的公开写入合同；模型定价通过 `call::services::settings` 的类型化服务调用。历史统计补入及手动修正未找到公开写入入口，需要与 CPR 开发者确认或补充宿主能力。详细证据与沟通草稿见 `write-capability-audit.md`。不能用插件独立统计页替代历史补入目标，也不能凭空假定 SDK 接口存在。
