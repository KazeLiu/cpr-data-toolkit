# CPR 数据工具箱：历史数据补入与维护

记录日期：2026-10-13。项目名称为 CPR 数据工具箱，标识为 `cpr-data-toolkit`，开发目录为 `D:\code\cpr-data-toolkit`。CC Switch 是首个明确的导入来源。实现口径和任务顺序见已批准的 `implementation-plan.md`，首版源码已完成。

## 用户明确的五项需求

管理页面使用五个标签，标题与职责已按用户要求收敛如下：

| 标签标题 | 职责 |
| --- | --- |
| API 导入 | 首先接入 CCS 的站点配置，预览、去重并导入 CPR 账号管理 |
| 用量导入 | 首先接入 CCS 的历史 token 计数和请求统计，去重后补入 CPR |
| 手动调整 | 填写 token 和请求次数的增减量，预览变更并在提交前提醒统计指标可能不一致 |
| 模型定价 | 同步模型价目，批量新增、修改和删除价格，并使其对 CPR 的计价生效 |
| 模型UA定制 | 按请求模型名的匹配规则覆盖上游 UA，未命中保留 Key 原有身份 |

五个标签分别承载这五项功能，不增加用量分析标签。价格同步和批量维护在“模型定价”标签内完成；前两个标签首个来源为 CCS。

### 1. 导入去重后的历史用量

使用场景：之前使用 CC Switch 连接中转站，历史统计保存在 CCS；切换到 CPR 直连后，保留过去的统计信息并补入 CPR。

目标按补入 CPR 原有统计理解，展示沿用 CPR 的统计视图；插件负责导入与维护。需处理来源内部重复和重复导入，保留可用的历史时间、账号/站点、模型、token 分类、请求次数及原始统计口径。

去重至少涉及：同一文件重复导入、来源内代理和会话记录重复、导入日期与 CPR 已有记录交叠。不能把相似 token 数和相近时间直接当作跨系统请求身份一致的证明。

CPR v3.26.1 仍未找到公开补入入口。本阶段已按批准计划实现来源解析、去重和预览，确认导入提示「上游接口未开放」；预览不会作为原生补入，也不持久化成已导入批次。历史写入保留为后续依赖。

### 2. 手动增减 token 与请求次数

目标是补录遗漏量或减去错误量。用户已选择简化输入：填写 token 与请求次数的增减量，不要求提供模型、费用或逐请求耗时。当前阶段只做界面，保留确认前的派生指标提醒。

本阶段交互：输入增减量 → 显示本次变化及真实原值可用时的调整后预览 → 弹窗提醒 → 确认后提示「上游接口未开放」。弹窗按钮为「取消」和「确认调整」，界面文案遵守宿主短语约定。

建议的弹窗文案：

> 确认 Token 与请求次数增减
>
> 未提供模型、费用和耗时信息，总计费、首字均值等指标无法随补录量完整更新，可能与调整后的总量不一致
>
> 请确认填写的数字后继续

这里的“不一致”指手动补录缺少明细，不能据此补齐费用或性能观测，并非断言每个已有均值必然计算错误。首版不根据手填总量猜测模型、费用、耗时或成功/失败分类，也不尝试通过假造请求明细补齐指标。

用户已明确：宿主没有公开接口时只实现界面。2026-10-13 核对 CPR v3.26.1 后仍未找到修正入口，点击「确认调整」提示「上游接口未开放」，保留输入，不修改或模拟修改统计总值。

预览仅基于同口径的真实原值，明确统计范围；无法读取原值时不填零。缺失耗时不能填成零混入均值，未知费用不能等同于免费。后续接入真实写入时，减量边界和派生指标按新宿主合同核对。

修正记录、撤销和归属等真实写入能力等待宿主合同；本阶段不创建空接口。

### 3. CCS 站点连接导入 CPR 账号管理

提取 CCS 中 Claude、Codex 和 Gemini 保存的站点名称、上游地址与 API Key，按用户选择接入 CPR 的 OpenAI Responses 兼容上游，不按来源应用或协议拦截，不自动验证兼容性或改写 API 路径。

来源表格显示「来源名称、应用、API、Key、接入」，支持多选及跨页全选后一键接入。API 后有复制按钮；Key 默认隐藏，后面的眼睛和复制按钮按需读取明文。相同 API 与 Key 合并为一个上游，名称不同时在确认弹窗选择保留名称。多个已有 CPR 账号匹配时选定一个更新，不删除其他账号。保存逐项显示实际结果，结果未知时停止后续接入。

来源适配层可扩展；不同来源复用统一导入流程与 CPR 账号写入路径。

### 4. 模型定价同步与批量维护

目的：OpenAI 兼容接口可能提供 GPT 以外的模型，需要批量新增、修改、删除和同步模型价格，并使其对 CPR 的计价生效。

已核对 v3.26.1 的公开 API 与 SDK 定价合同：

- 价目键为 Provider 与精确上游模型 ID，Provider 为 `openai` / `xai`
- 更新允许非内置模型；未在内置或同步价目中登记的模型需要提供 standard 价格
- 同一请求可更新 1～500 个模型；该请求的 change 是统一操作，不等于一个请求内任意逐行不同价格
- 删除不适用于内置模型；内置模型可重置人工覆盖
- models.dev 的现成同步限定 OpenAI/xAI，其他模型来源需要另外映射
- 改价影响后续本地估算和相应限额，不自动重算历史费用

依据：[CPR 模型定价合同](https://github.com/zyycn/codex-proxy-rs/blob/5358de53ddd4bda529cb63c422fd5c6af070f9c9/backend/crates/gateway-plugin/sdk/src/call/services/settings.rs)。首版按批准计划沿用全局价目，并通过宿主受管 HTTP 获取 models.dev 社区价目，核对目标 Provider 和精确模型 ID 后写入。缓存价格缺失或留空按零处理；价目表全选当前筛选结果，社区与同步表全选本页。

0.5 增加社区价目表格关键词过滤，以及「社区模型 ID」表头的包含筛选。两项条件同时生效，忽略大小写，在整个选定来源过滤后再分页，翻页保持已应用的条件。

用户希望按当前价目补全或覆盖历史请求费用，并确认 v3.26.1 没有公开写回接口时暂时只做弹窗。「价格同步」位于社区价目按钮右侧，每次打开默认选择「只补全缺失费用」，也可选择「覆盖全部历史费用」；已有 0 费用不视为缺失。确认提示「上游接口未开放」，不修改历史费用，不扩展本次宿主修改范围。

### 5. 模型UA定制

用户要求新增独立标签，名称准确为「模型UA定制」。OpenAI 兼容 API Key 上游可能同时提供 Grok、Gemini 等模型，需要按模型设置不同 UA。

- 请求模型名包含 grok 时，使用 grok 规则中的 UA
- 包含 gemini 时，使用另一条规则中的 UA
- 未命中任何规则时不改写，保留当前 Key 统一身份
- 不改变模型名、上游协议、地址、凭据或账号选择

包含匹配忽略大小写，从上到下首条启用规则生效；支持启停、排序及匹配预览。UA 必填，originator 和 version 为可选配套头，未填写的头不变更。范围复用 CPR request 绑定，推荐限定个人反代使用的 Client Key。安全验证读取所选 Key 可见模型并共用正式改写逻辑，缩短至插件出口，不发送真实模型请求。

用户反馈 UA 未修改成功后，新增实际请求日志表：时间、模型名称、规则、替换前 UA、替换后 UA。记录已改写和未命中的真实调用，模型缺失及规则读取失败单独标注；入口 UA 与 Key 默认画像区分，配套头变化可展开查看。日志只在进程内存保留最近 200 条，支持刷新、分页和清空，重启清空。

v3.26.1 的公开中间件合同已确认账号和画像先生成头，插件同名头随后覆盖。[SDK 请求中间件](https://github.com/zyycn/codex-proxy-rs/blob/5358de53ddd4bda529cb63c422fd5c6af070f9c9/backend/crates/gateway-plugin/sdk/docs/capabilities.md#模型请求与-attempt)
