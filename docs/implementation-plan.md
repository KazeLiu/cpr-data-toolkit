# CPR 数据工具箱实现计划

- 日期：2026-10-13
- 状态：0.5 社区价目过滤与历史费用同步弹窗已完成，Linux ARM64 插件包已生成，等待用户测试后再发布多平台 Release
- 项目：`D:\code\cpr-data-toolkit`

用户已批准本计划，源码实现及当前确认范围见第五节。

## 1. 五个标签页与交付范围

| 标签页 | 本阶段实现 | 完成标准 |
| --- | --- | --- |
| API 导入 | CCS 连接解析、来源表格、查看与复制、多选／全选、去重和宿主账号保存 | 按选择接入 Responses 账号，同连接选择名称后只保存一次，逐项显示实际结果 |
| 用量导入 | CCS 历史用量解析、来源内去重、汇总和预览 | 明确显示尚不能补入 CPR，确认导入提示「上游接口未开放」，不产生成功回执 |
| 手动调整 | Token 总量与请求次数的正负增减表单、预览和确认弹窗 | 点击「确认调整」提示「上游接口未开放」，不修改宿主或浏览器中的统计总值 |
| 模型定价 | 全局价目读取、宿主来源同步、批量新增、修改、重置与删除 | 经公开 settings 服务保存，逐项反映成功、失败及结果未知 |
| 模型UA定制 | 模型包含规则、UA 及可选配套头的维护和请求中间件 | 命中时覆盖指定头，未命中时保留 Key 原有身份 |

标签名称及顺序固定为：**API 导入、用量导入、手动调整、模型定价、模型UA定制**。不增加独立用量分析页。

用量导入的最终目标仍是补入 CPR 原生统计。本阶段的解析和预览不代表历史写入能力已经完成；缺失的宿主合同作为后续依赖保留。

## 2. 宿主基线与已确认接口

- 用户当前 CPR 为 `v3.26.1`；SDK 和打包 CLI 固定到该标签对应提交 `5358de53ddd4bda529cb63c422fd5c6af070f9c9`，不追随 main。
- 新插件最低宿主版本定为 `3.26.1`，清单使用 `>=3.26.1, <4.0.0`；更高版本不能仅凭范围表达式视为已经验收。
- UI 沿用已核对的 `@codex-proxy/ui` v0.4.0 固定提交 `db615f3d72975e0d09847a07d03ed5fe7ba8c8b0`，Vue 和页面样式一起编入包内。
- 账号创建与替换：`host.auth.save`；替换必须携带精确 credential revision。
- 定价：`call::services::settings::{Pricing, PreviewPricingSync, Sync, Update}`，由插件后端经 `HostClient::service` 调用。
- UA：公开 request 中间件读取请求模型，通过 header 增量修改进入上游；宿主账号和画像先生成请求头，插件同名头随后覆盖。
- 统计：已核对 v3.26.1 的公开 SDK、回调分派、服务注册和管理路由，仍未找到外部历史用量或 Token／请求次数修正的写入入口。已有用量路由用于 GET 查询。

完整证据见 [写入能力核对](write-capability-audit.md)。不修改 CPR 核心代码或数据库，不用私有状态、预算重置或虚构请求代替原生统计写入。

## 3. 本计划采用的实现口径

以下为本次已批准的实现口径。

### 3.1 模型UA定制

**规则与匹配**

- 匹配客户端请求中的公开模型名，不匹配上游响应报告的模型，不修改 model，不切换 Provider、账号或上游地址。
- 首版只有「包含」匹配，忽略大小写；不加入正则、通配符或模型别名功能。
- 按列表从上到下查找第一条已启用的命中规则，后续规则不再合并。
- 每条规则包含稳定 ID、启用状态、模型关键词、`User-Agent`；列表顺序就是优先级。
- `originator`、`version` 放在规则编辑的可选配套字段中；填写时覆盖，未填写时保持原值。只开放这些固定字段，不提供任意请求头编辑。
- 关键词和 UA 不能为空；头值在后端用 HTTP 头格式规则校验，拒绝换行及不合法值，不静默截断或替换。
- 未命中、规则全部停用或缺少模型名时，不做任何头修改，直接沿用当前 Key 的有效身份。
- 命中时先移除本请求内同名头，再追加规则值，保证本插件不会产生多个 UA；其他未配置头保持原样。
- 实现入口可以参考[请求中间件文档](https://github.com/zyycn/codex-proxy-rs/blob/a9ce01f91fbe29d945c7642b77792f19af1503c3/backend/crates/gateway-plugin/sdk/docs/capabilities.md#%E6%A8%A1%E5%9E%8B%E8%AF%B7%E6%B1%82%E4%B8%8E-attempt)，覆盖顺序见[上游请求头处理](https://github.com/zyycn/codex-proxy-rs/blob/a9ce01f91fbe29d945c7642b77792f19af1503c3/backend/crates/providers/openai/src/transport/headers.rs#L230)

**页面与保存**

- 页面以紧凑规则表格为主，提供新增、编辑、启停、上移、下移、删除和显式保存。
- 增加一个模型名输入框，用同一套后端匹配逻辑预览命中规则及覆盖字段；该预览不发送模型请求、不消费上游额度，也不读取 Key 明文。
- 初始规则列表为空，不预填未经核实的 Grok／Gemini UA。
- 规则保存在声明过 schema 和容量的插件私有状态中，更新带精确状态版本；并发冲突要求重新读取，不自动覆盖。
- 每个逻辑请求读取一次规则快照。已经进入该请求的头改写不因编辑规则在中途变化。

**作用范围**

- 使用 CPR 原有的 request 中间件绑定限定 Client Key，不在插件中复制另一套 Key 范围配置。
- 推荐管理员把绑定限定到个人反代使用的 Client Key；宿主绑定范围为空表示全局，使用说明明确写出这一点。
- 本插件只声明 request 挂载，不重复在 request 与 attempt 两层改写。

示例：`grok-4.7` 命中关键词 grok 使用该行 UA；`gemini-…` 命中另一行；`gpt-…` 未命中时仍用 Key 原有身份。

**实际请求日志**

- 记录真实 request 中间件调用，展示时间、模型名称、命中规则、替换前 UA、替换后 UA；匹配预览和安全验证不进入日志
- 已改写、未命中、模型缺失及规则读取失败分别标注，`next` 调用失败时补充下游失败状态；规则读取失败仍返回原错误，不改成空规则继续执行
- 替换前为插件入口头，替换后为本插件交给宿主的头，不将入口 UA 标成 Key 默认 UA 或最终出站值；变化的 `originator`、`version` 可展开查看
- 进程内存保留最近 200 条，每页 25 条，最新在前；支持刷新和清空，重启清空，不写入规则状态或宿主数据库
- 日志仅采集三个身份头，不采集认证头、Cookie、请求正文或凭据；每个身份头最多采集 4096 字节，超出明确标注，实际改写不截断

**防范于未然**

- 需要有一个测试的地方，能测试从入口到出口的全链路是否能真正的替换，入口是调用/v1/responses，出口要到调用上游的最后一步（但是请求不能真的发出去），然后看UA有没有被修改成功。模型名称就类似于插件demo项目里面一样，选择了key后拉来的模型名称。如果链路无法完成这么长，就适当缩短。

### 3.2 API 导入

- 首版来源采用 CCS 的完整手动 SQL 导出，优先使用其已有导出入口，避免直接读取运行中的数据库或遗漏 WAL。
- 不把 CCS 的 WebDAV 同步导出当作完整历史文件。首版不连接本机真实来源库，不支持持续同步或 OAuth 迁移。
- 外部 SQL 仅进入隔离临时 SQLite 库；使用执行授权限制允许的建表、索引和写入，拒绝 ATTACH、外部文件、扩展、虚拟表等操作。
- SQLite 创建索引同时触发 `Reindex` 授权检查，该动作仅在隔离内存库的 `main` 中允许，不放开其他数据库或操作。
- 上传通过插件自己的管理路由分块传输，单块 256 KiB，文件上限 64 MiB；避免把整份文件塞进宿主单次管理正文。上传按顺序提交，失败或取消时停止，不自动重放写入。
- 实现使用后端内存暂存上传材料和临时 SQLite 库，不落原始文件。解析成功后释放 SQL，只保留有界解析来源；取消、明确失败、闲置 15 分钟或进程退出后清理。最多两个上传和两个解析来源，不访问或清理来源目录。
- 适配首版已核对的 CCS schema 20 表和列。导出缺少版本信息时依据完整结构签名识别；结构不足或未知时返回兼容错误，不修改输入来适配。
- 来源身份为 `(app_type, provider_id)`。保留 URL、协议、模型和端点事实，提取 Claude、Codex 和 Gemini 的地址与 Key，不按应用或协议拦截接入。
- 用户选择的接入类型统一为 OpenAI Responses 兼容上游，不自动验证协议或修改 API 路径；缺少有效地址或 Key 时在该来源行说明原因。
- 表格列为来源名称、应用、API、Key、接入，支持逐项勾选及跨页全选。API 可一键复制；Key 默认隐藏，主动点击眼睛或复制按钮时按需读取，不进入日志或浏览器持久存储。
- 重复导入依据来源映射及后端必要的连接事实核对，不按名称判断凭据相同。
- 新建账号由宿主生成 ID。已导入项明确区分无变化与需要更新，更新经用户确认并使用 credential revision。
- 逐项记录成功、跳过、失败及结果未知。账号保存与映射状态保存不是同一事务；超时或映射保存失败后先核对宿主事实，不能盲目重新创建。
- 相同 API 与 Key 合并为一个上游，接入确认弹窗中用 radio 选择保留名称；若匹配多个宿主账号，同时选择要更新的具体账号，其他账号保持原样

### 3.3 用量导入

- 与 API 导入复用上传和 CCS 适配，不建立第二套来源加载流程。
- 读取 `proxy_request_logs`、会话用量和 `usage_daily_rollups`，保留实际存在的应用、供应商、模型、来源时间和缓存语义。
- 按来源的 input token 语义归一，采用 CCS 已核对的有效用量规则处理代理日志与会话重复。
- 明细与日聚合分开展示粒度及时间覆盖；不能把日聚合变成请求明细，重叠部分不能重复累计。
- 预览展示数量、时间范围、Token 分类、请求数、去重或排除项；未知归属和费用保持未知。
- 页面明确标注「上游接口未开放」。点击确认导入显示同一提示，不发起虚构的宿主写入，不持久化成已导入批次。
- 原生历史补入保留为后续接入任务，恢复条件是 CPR 提供覆盖来源身份、幂等、聚合、部分失败和结果查询的公开写入合同。

### 3.4 手动调整

- 输入 Token 总量和请求次数的正负整数增减量，不要求模型、费用或耗时。
- 原值由插件后端通过公开 HTTP 分派只读查询宿主用量汇总，使用宿主已有时间范围参数；页面仍只调用插件自己的管理路由。
- 显示本次增减；调整后预览只基于宿主公开查询返回的同口径原值，明确标注所选统计范围，不把一个时间窗口的汇总称为全部历史总量。
- 没有可用原值时显示「当前统计不可用」，不把读取失败填成零，也不据此生成调整后总数。
- 整数用可精确表达的字符串及整数运算处理，不用 JS 浮点数承载超出安全范围的 Token 总量。
- 保留提交前确认弹窗及「取消」「确认调整」按钮。提醒沿用已确定含义：未提供模型、费用和耗时，派生指标可能无法随总量完整更新。
- 点击「确认调整」显示准确文案 **「上游接口未开放」**，保留输入，允许继续编辑，不提示成功、不刷新成已经修改的总值。
- 本阶段不做修正量后端写入、修正记录或撤销接口；不建立将来接口的空处理器。

### 3.5 模型定价

- 首版沿用 CPR 全局价目，不增加站点或账号独立定价。
- 提供 Provider、模型筛选，显示默认／同步／人工覆盖来源；金额使用十进制字符串。
- 同步使用宿主已公开的预览和确认流程。宿主自动同步范围仍受其来源约束，不能按模型关键词把其他品牌价目自动归入原生 Provider。
- OpenAI 兼容上游上的 Grok、Gemini 等模型可以按精确上游模型 ID 手工批量新增和维护；社区价目经宿主受管 HTTP 读取 models.dev，不另建抓取服务，也不自动映射品牌或模型别名。
- 不同单价按实际 `UpdatePricing` 合同分组或逐项提交；一次请求最多 500 个模型，并应用同一个 change。
- 内置模型支持重置覆盖，不允许删除；非内置模型允许删除。批量删除前确认。
- 改价只影响后续本地估算，不自动重算历史费用。不把本地估价写成供应商账单。
- 部分成功和结果未知逐项显示；重新读取确认现状后才允许继续操作，不把跨请求更新显示成原子事务。
- 从 models.dev 获取社区价目。
- 价目表可全选当前筛选结果，社区和同步表可全选本页，支持半选反馈；单次批量写入最多 500 个模型。
- 缓存价格缺失或留空按零处理，输入和输出价格仍须有效；已提供但非法的社区缓存价格跳过，不用零掩盖无效数据。
- 提交 SDK 的每个价格档位只含 `input`、`output`、`cacheRead`、`cacheWrite`，不携带页面行 ID、Provider 或模型名等行元数据。
- 社区价目支持名称、模型 ID 或价格关键词，以及模型 ID 包含条件，两项条件组合生效；在整个选定来源过滤后再分页，翻页沿用已应用条件。
- 「价格同步」位于社区价目按钮右侧，每次打开弹窗默认只补全缺失费用，也可选择覆盖全部历史费用；已有 0 费用不视为缺失。v3.26.1 缺少历史费用写回合同，本阶段确认仅提示「上游接口未开放」，不发起写入或修改页面中的费用。

## 4. 文件与模块职责

当前源码按以下职责组织，只创建实际使用的模块。

| 路径 | 职责 |
| --- | --- |
| `Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml` | Rust 插件与固定 SDK 依赖 |
| `plugin.json` | 身份、版本、management、request middleware、私有状态和静态资源声明 |
| `src/main.rs` | 标准输入输出会话、类型化处理器注册与来源过期清理 |
| `src/management.rs`、`src/api.rs` | 插件自有上传、预览、账号导入、价目和 UA 管理路由、边界输入与响应 |
| `src/sources.rs` | CCS 内存安全加载、结构检查、连接和用量转换 |
| `src/accounts.rs` | 宿主账号保存、来源映射及逐项恢复 |
| `src/pricing.rs` | 类型化定价调用及批量结果 |
| `src/model_ua.rs` | 规则校验、匹配预览、请求头改写及有界内存日志 |
| `src/state.rs` | 实际使用的规则和导入映射状态版本处理 |
| `src/host.rs` | 宿主元数据回调与凭据二进制载荷的明确区分 |
| `web/` | Vue SFC、TypeScript、公开 UI 组件及自包含构建配置 |
| `web/src/api/` | 页面经宿主桥调用的集中业务 API 和边界类型 |
| `web/src/features/` | 五个标签页，各自的表单、表格和对话框 |
| `docs/`、`README.md` | 使用入口、功能边界、实施状态及后续打包说明 |

前端沿用宿主紧凑表格和表单、公开主题 tokens，不重复渲染页面标题，不另建侧栏或固定明暗主题。复杂配套头折叠显示；表单错误放在字段旁；异步提交显示进度并防止重复点击。重排同时提供上移／下移，不能只依赖拖拽。

## 5. 按依赖顺序实施

- [x] **T1 插件基础**：创建固定依赖、清单、SDK 会话与管理页面桥；注册五个标签页和有实际用途的路由。声明状态 schema、记录数与字节容量，更新忽略规则防止来源秘密材料提交。完成标准：清单、处理器、资源与源码入口一致。
- [x] **T2 模型UA定制**：完成规则表、编辑保存、匹配预览、状态版本冲突和 request 中间件。依赖 T1。完成标准：命中覆盖、首条优先及未命中透传的调用链完整，正文和响应流不被替换。
- [x] **T3 模型定价**：完成全局读取、同步预览确认、批量维护和逐项结果。依赖 T1。完成标准：所有真实操作经公开类型化服务，不绕过宿主桥或模拟保存。
- [x] **T4 CCS 加载与 API 导入**：实现有界上传、安全 SQL 加载、schema 20 适配、脱敏预览、选择和账号保存恢复。依赖 T1。完成标准：来源身份不混淆、凭据不外泄、重复项与未知提交状态不会自动重复创建。
- [x] **T5 用量导入预览**：复用 T4，完成 Token 归一、来源内部去重、明细与日聚合覆盖检查和未开放提示。完成标准：可以检查来源数据，不能把预览或私有状态冒充 CPR 原生历史。

## 7. 风险与恢复

- UA 规则保存冲突时保留未提交编辑，重新读取后由用户决定；状态读取失败按明确错误和宿主绑定失败策略处理，不暗中当作空规则。
- 其他中间件或隐私规则也可能修改同名头，最终出站值需在目标配置下确认。CPR v3.26.1 的可替换前导重试例外不适用于启用中间件链的请求，本插件不增加自己的重放机制。
- 账号写入与私有映射写入不在同一事务，保存回执丢失时保持结果未知并核对宿主，不自动重复创建。
- 定价批量操作可能部分成功，保留逐项结果，重新读取已保存价目后决定后续动作。
- 未开放的两项统计写入由 CPR 公共接口提供方解除依赖；插件后续按新合同接入，不把修改源码版本号或预算重置当作恢复条件。
- 插件停用停止后续 UA 改写，但已导入账号和已保存价格不会自动撤销；需要管理员通过原生管理恢复。
